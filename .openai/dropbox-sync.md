# Dropbox file inventory for this Site

The user selected one existing Dropbox folder for the AI-практик course. The canonical folder configuration is stored in the Site's secret runtime configuration. Retrieve it through the authenticated updater; do not copy private shared links or credentials into code or prompts.

1. Call Sites `get_site` for this project. The caller must still be the Site owner. Preserve private access for the owner and explicitly allowed staff; stop if the Site has become public or workspace-wide. Never change its audience. The updater has a separate secret hash check in addition to the Site access boundary. Obtain the existing `siwc_bypass_bearer_token` in memory. If access or token is unavailable, stop and report the blocker; never relax access or create credentials for an unrelated service.
2. Open the current Site source with the Sites source helper and a fresh source repository credential. No install/build/push is needed. Use `scripts/dropbox-sync-client.mjs` from that checkout. Launch it in a retained PTY, wait for its ready message, and send one newline-terminated JSON object through hidden stdin. The helper accepts `{action:'status',origin,token}` and `{action:'import',origin,token,snapshot}`. Keep the token out of argv, files, tool output and the task prompt.
3. Read status to get the exact configured folder id, path and name. Inspect that same folder through the user's connected Dropbox. List all its files recursively, following every cursor until `has_more` is false. Never scan other folders.
4. Create a complete metadata snapshot: `{complete:true,files:[{id,name,path,size,modifiedAt}]}`. Use exact returned Dropbox file IDs and paths. For size prefer `file.size`; use returned modified time. If needed, retrieve metadata for the selected file to obtain missing values. Include files only; do not fabricate dates, paths, sizes, or links. If a page or metadata request fails, do not submit an incomplete snapshot.
5. POST the snapshot through the helper. No new shared links are created. The importer reuses the user's existing shared folder URL, classifies names such as L07, Lesson7 and slides, and upserts metadata without copying large video files or deleting anything. Unknown lesson codes stay in the course inbox.
6. Read status again to verify the timestamp and file count. Do not republish the Site on routine runs. Report errors clearly; do not claim that a saved schedule proves a successful run.

The import is idempotent. It preserves uploaded files, lesson content, original schedules and delivery deadlines. A changed selected video invalidates checked timecodes and marks handed-off content as changed.
